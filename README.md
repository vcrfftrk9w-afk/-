# ViralCoach — ИИ-наставник по росту в TikTok

Красивое SPA-приложение, которое помогает создателям контента быстрее расти
в TikTok: анализирует профиль, показывает точки роста, подсказывает
актуальные тренды с пошаговыми инструкциями по съёмке, генерирует готовые
идеи для видео и ведёт по персональному 90-дневному плану к популярности.

## Стек

- React 18 + TypeScript + Vite (фронтенд)
- Express + Playwright (бэкенд `server/` — автоматический импорт публичного профиля TikTok)
- Tailwind CSS — оформление в стиле TikTok (тёмная тема, неоновые акценты cyan/pink)
- Framer Motion — анимации переходов, счётчиков, прогресс-баров, раскрывающихся карточек
- Zustand (+ persist) — состояние приложения с сохранением в localStorage
- canvas-confetti — праздничный эффект при завершении плана роста

## Как запустить

```bash
npm install
npx playwright install chromium   # один раз, для автоимпорта TikTok
npm run dev:full                  # фронтенд (5173) + backend-API (3001) вместе
```

Приложение откроется на `http://localhost:5173`. Кнопка «Импортировать по
юзернейму» в форме реальных данных работает только когда запущен `dev:full`
(или отдельно `npm run server`) — без бэкенда форма прекрасно работает и в
чисто ручном режиме.

Только фронтенд, без автоимпорта:

```bash
npm run dev
```

Продакшн-сборка (фронтенд + бэкенд одним процессом на одном порту):

```bash
npm run build
npm run start   # http://localhost:3001, отдаёт и статику, и /api
```

Или классический статический превью без бэкенда:

```bash
npm run build
npm run preview
```

## Как устроено приложение

1. **Онбординг (`/`)** — юзернейм и ниша, затем выбор режима анализа:
   - **Реальные данные (рекомендуется)** — жмёшь «Импортировать по
     юзернейму», и бэкенд сам заходит на твою публичную страницу TikTok и
     забирает подписчиков + статистику последних видео (просмотры, лайки,
     комменты, репосты, дата, хэштеги). Всё подставляется в форму — остаётся
     проверить и нажать «Проанализировать». Если автоимпорт не сработал
     (TikTok заблокировал запрос, страница недоступна, структура изменилась)
     — те же поля легко заполнить вручную, скопировав цифры из TikTok Studio
     → Аналитика. Весь дашборд в любом случае считается по этим настоящим
     цифрам — без единого случайного числа.
   - **Демо-режим** — сгенерированный пример для ознакомления с интерфейсом,
     явно помечен как демо на дашборде.
   Данные можно в любой момент обновить на странице `/update-data` (форма
   подставляет ранее введённые видео, чтобы не вводить всё заново, и там же
   можно повторно нажать автоимпорт).
2. **Дашборд (`/dashboard`)** — индекс роста, 6 ключевых метрик (вовлечённость,
   регулярность, сила хука, использование трендов, удержание, хэштеги),
   график роста подписчиков, тепловая карта лучшего времени для публикаций,
   баланс контент-пилларов и персональные советы ИИ-коуча по слабым местам.
3. **Радар трендов (`/trends`)** — курируемая база актуальных форматов
   (дуэт-челленджи, transition, storytime, POV, тренды под конкретную нишу —
   например, для ниши "Танцы" — синхронные дуэты и разбор хореографии по
   шагам), с полной инструкцией по съёмке, примером подписи и хэштегами.
4. **Генератор идей (`/ideas`)** — на основе ниши, слабых мест и радара
   трендов собирает готовые концепции видео: хук, тайминг по секундам,
   шот-лист, музыка, подпись, хэштеги и рекомендованное время публикации.
   Идеи можно сохранять.
5. **План к успеху (`/roadmap`)** — 4 фазы на 90 дней (фундамент → набор
   темпа → ускорение → прорыв) с чек-листами задач, персонализированными под
   слабые метрики профиля. Прогресс сохраняется, при 100% — конфетти.
6. **Полный гайд (`/guide`)** — статья "как стать популярным в TikTok":
   как работает алгоритм, мастерство хука, регулярность, trend-jacking,
   съёмка и монтаж, хэштеги и SEO, еженедельная аналитика, частые ошибки,
   финальный чек-лист перед публикацией.

## Важно про источник данных (честно о том, как это работает)

Официальный API TikTok (Display/Research API) требует регистрации
приложения разработчика и одобрения TikTok — это внешняя процедура, которую
нельзя пройти автоматически. Вместо неё бэкенд (`server/`) сам открывает
*публичную* страницу профиля headless-браузером (Playwright/Chromium) —
ровно то же самое, что видит любой не залогиненный посетитель — и вытаскивает
из неё подписчиков, лайки и статистику последних видео (просмотры, лайки,
комменты, репосты, дата, хэштеги). Учти:

- **Это работает только с публичными аккаунтами.** Приватный профиль,
  несуществующий юзернейм и т.п. — понятная ошибка вместо тихого фейка.
- **Это заведомо непрочная интеграция.** TikTok периодически меняет разметку
  страницы и активно детектирует автоматизированный доступ (может показать
  капчу/проверку «ты не робот»). Парсер (`server/tiktokScraper.mjs`) пробует
  сначала встроенный JSON-снапшот страницы, затем видимые `data-e2e`-атрибуты
  как запасной вариант, и при любом сбое возвращает понятный код ошибки
  (`NOT_FOUND`, `PRIVATE`, `BLOCKED`, `TIMEOUT`, `PARSE_ERROR`) — форма в
  интерфейсе никогда не тихо подставляет фейковые числа при сбое, а просто
  остаётся пустой для ручного заполнения.
- **Я не могу протестировать сам скрапинг** из этой среды разработки:
  исходящие запросы к `tiktok.com` заблокированы политикой сети песочницы
  (проверено — соединение отклоняется на уровне прокси). Весь остальной путь
  (сервер, Playwright, обработка ошибок, UI) прогнан и подтверждённо работает
  «от и до» на реальном тестовом сценарии — не хватает только последнего шага
  (реальный ответ tiktok.com). Если структура страницы TikTok на момент
  твоего запуска отличается от того, под что писался парсер — самое вероятное
  следствие: ошибка `PARSE_ERROR`/`BLOCKED` вместо реальных данных. В этом
  случае ручной ввод (та же форма, без единой лишней настройки) остаётся
  100%-рабочим fallback-путём.

Что считается из полученных данных (вручную ли, автоимпортом ли — неважно,
путь один и тот же, `src/lib/realAnalysis.ts` → `analyzeRealProfile()`):
вовлечённость, регулярность публикаций, баланс контент-пилларов, лучшее время
постинга и хэштег-стратегия — напрямую из чисел, без единого `Math.random()`.
Метрики, которые физически нельзя измерить без доступа к приватной аналитике
TikTok (досмотр/удержание, сила хука), честно помечены в интерфейсе тегом
«оценка» — это прозрачная прокси-формула от измеримых метрик, а не выдуманное
число.

Демо-режим (`src/lib/analysis.ts` → `analyzeProfile()`) остаётся отдельно —
детерминированный генератор на основе юзернейма и ниши, только для
ознакомления с интерфейсом, явно помечен баннером «демо-данные» на дашборде.

Хочешь подключить официальный Display API через OAuth вместо скрапинга —
структура совместима: собери `RealProfileInput` (см.
`src/lib/realAnalysis.ts`) откуда угодно и вызови `analyzeRealProfile()`; весь
остальной UI не завязан на способ получения данных.

- `src/lib/trends.ts` → `TRENDS` — вручную курируемый плейбук актуальных
  форматов (не live-парсинг ленты TikTok); при желании `TRENDS` можно
  подгружать из внешнего trend-intelligence сервиса, сохранив тип `Trend`.

## Бэкенд (`server/`)

```
server/
  index.mjs           — Express: GET /api/tiktok-import/:username, троттлинг
                         15с/IP, в проде отдаёт собранный dist/ на том же порту
  tiktokScraper.mjs    — Playwright-логика скрапинга публичного профиля
```

`vite.config.ts` проксирует `/api/*` на `http://localhost:3001` в dev-режиме
(`API_PORT` меняет порт бэкенда при необходимости).

## Структура проекта

```
src/
  lib/            — вся бизнес-логика (аналитика, тренды, идеи, roadmap, гайд)
  store/          — zustand-стор с persist в localStorage
  components/
    layout/       — каркас приложения (сайдбар, мобильная навигация, фон)
    ui/           — переиспользуемые примитивы (карточка, заголовок, счётчик)
    charts/       — кастомные SVG-визуализации (индекс роста, график, тепловая карта)
  pages/          — страницы приложения (Landing, Dashboard, Trends, Ideas, Roadmap, Guide)
```
