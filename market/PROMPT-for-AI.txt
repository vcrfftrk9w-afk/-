Ты продолжаешь разработку Sauda — маркетплейса для Казахстана (как FunPay и Playerok): игровая валюта, донат по ID, аккаунты, подписки, услуги и вещи; сделки через гаранта, цены в тенге, вывод на Kaspi, русский и казахский язык. Версия кода: {{version}}.

Во вложении весь исходный код. Сначала прочитай README.md (особенно «Карта файлов» и «Правила для ИИ»), потом market/README.md.

Как устроено:
- Сайт — папка market/: чистые HTML/CSS/JS без сборки и без фреймворков. Скрипты подключены в market/index.html по порядку. Работающий сайт: https://vcrfftrk9w-afk.github.io/-/market/
- Сервер — PostgreSQL в Supabase: закрытая схема sauda и функции public.sauda_*, которые сайт вызывает через POST /rest/v1/rpc/sauda_*. Весь SQL — supabase/migrations/*_sauda_*.sql, файлы 0100–0700 уже применены к базе.
- sauda.html — тот же сайт одним файлом (собирается командой node tools/sauda-pack.js). Править нужно файлы в market/, а не sauda.html.

Обязательные правила:
1. Вёрстка только через html`…` из market/js/core.js (он экранирует подставленное); текст от людей никогда не вставлять через innerHTML напрямую.
2. Каждый видимый текст — по-русски через t('…') и сразу его перевод в market/js/i18n-kz.js.
3. Суммы из полей ввода разбирать через Fmt.amount().
4. Деньги считает только сервер; баланс меняется только через sauda.money(). Новые функции для сайта — public.sauda_*, security definer, set search_path = '', ошибки через raise exception 'код' (текст ошибки для человека — в ERRORS в core.js), в конце файла — блок прав, как в 20261017000700_sauda_levels.sql.
5. Изменения SQL — только НОВЫМ файлом миграции с более поздним номером (create or replace function …, alter table … add column if not exists …). Старые файлы не переписывать.
6. Не меняй market/js/config.js (адрес базы), если я об этом не попрошу.
7. Присылай каждый изменённый или новый файл ЦЕЛИКОМ и пиши его путь. В конце — короткий список: какие файлы выложить на GitHub и какой SQL выполнить в Supabase → SQL Editor.
8. Если умеешь запускать команды — после изменений прогони проверки из README.md: npm run db, перезапусти npm run dev, затем npm run test:api; снова npm run db и npm run test:ui; npm run i18n.
9. Меняешь SQL-функцию — бери её последнюю версию (файл с бо́льшим номером). Новые скрипты подключай ровно как <script src="js/имя.js"></script>, стили — только в css/sauda.css.
10. Отвечай мне по-русски и простыми словами: я не программист.
