# Sauda — исходники и как продолжить в другом ИИ

Версия: **{{version}}**.
Свежая версия всегда здесь: https://github.com/vcrfftrk9w-afk/-/releases/tag/sauda-latest
Сайт: https://vcrfftrk9w-afk.github.io/-/market/

Sauda — маркетплейс для Казахстана, как FunPay и Playerok: игровая валюта, донат по ID, аккаунты, скины,
подписки, услуги и вещи. Сделки через гаранта, цены в тенге, вывод на Kaspi, русский и казахский язык.

## Что в архиве

| Что | Зачем |
|---|---|
| `sauda.html` | **Весь сайт одним файлом.** Двойной щелчок — откроется в браузере тот же сайт с той же базой: те же лоты, аккаунты и деньги. |
| `PROMPT-for-AI.txt` | Текст, который нужно вставить в другой ИИ первым сообщением. |
| `market/` | Сайт по файлам — так он лежит на GitHub Pages. Его и правят. |
| `supabase/migrations/` | Сервер: база, деньги, сделки, чаты, админка, уровни — 9 файлов SQL для Supabase. |
| `tests/`, `tools/` | Автопроверки и запуск всего на своём компьютере (для ИИ, который умеет запускать команды). |
| `android-sauda/`, `.github/workflows/sauda-apk.yml` | Android-приложение (сайт внутри) и его сборка на GitHub. |
| `package.json` | Команды для проверок: `npm run db`, `npm run dev`, `npm run test:api`… |

## Как продолжить в другом ИИ — 3 шага

1. Скачайте `sauda-source.zip` и распакуйте.
2. Откройте новый чат с ИИ и прикрепите **весь архив** (Claude, ChatGPT, Gemini принимают zip; Cursor, Claude Code,
   Codex, Windsurf — откройте распакованную папку как проект). Первым сообщением вставьте текст из `PROMPT-for-AI.txt`.
3. В конце этого текста напишите, что улучшить. ИИ пришлёт изменённые файлы — выложите их (раздел «Как выложить обновление»).

Если ИИ не принимает архив, а только текст — давайте ему по 1–3 файла под задачу (карта ниже) и `README.md`.
Например, «поменяй кошелёк» → `market/js/views-account.js` и `market/css/sauda.css`.

## Карта файлов

**Сайт** (`market/`, чистые HTML/CSS/JS, без сборки — файлы подключены в `index.html` по порядку):

| Файл | Что внутри |
|---|---|
| `index.html` | Каркас страницы: шапка, меню снизу, порядок скриптов. |
| `css/sauda.css` | Весь дизайн: тёмная и светлая тема, телефон и компьютер. |
| `js/config.js` | Адрес базы Supabase и публичный ключ. Меняется, только если переезжаете на свою базу. |
| `js/core.js` | Основа: безопасная вёрстка `html```, перевод `t()`, форматы денег и дат (`Fmt`, `Fmt.amount` — разбор сумм), запросы `Api`, окна и уведомления `UI`, адреса `Router`, тексты ошибок `ERRORS`. |
| `js/i18n-kz.js` | Казахский перевод: «русская строка → казахская». |
| `js/components.js` | Общие куски: карточки и строки лотов, статусы заказов и заявок, тексты уведомлений, способы оплаты и вывода. |
| `js/views-shop.js` | Витрина: главная, каталог, игра и раздел, поиск, страница лота, профиль продавца. |
| `js/views-deal.js` | Мои заказы, страница заказа (выполнить, подтвердить, спор, отзыв), чаты (`ChatBox`). |
| `js/views-account.js` | Вход и регистрация, профиль, настройки, кошелёк (пополнение по коду, вывод, отмена), продажа лота, мои лоты, избранное, уведомления, подписки, Pro, рефералы, статистика, помощь, поддержка. |
| `js/views-admin.js` | Админка: обзор, споры, поддержка, пополнения, выводы, заказы, люди, лоты, жалобы, промокоды, настройки и запуск с настоящими деньгами. |
| `js/app.js` | Запуск: шапка, список адресов `#/…` и какой экран на каком, проверка новых сообщений. |
| `img/games/` | Логотипы игр и сервисов (`<id игры>.webp`, 128×128). Список тех, у кого он есть, — `GAME_ICONS` в `js/components.js`. Логотип, загруженный в админке («Игры»), важнее файла. |
| `sw.js`, `manifest.json`, `icons/` | Установка на телефон как приложение и работа без сети. |

**Сервер** (`supabase/migrations/`, PostgreSQL в Supabase; файлы применяются по порядку номеров):

| Файл | Что внутри |
|---|---|
| `…0100_sauda_core.sql` | Таблицы (схема `sauda`) и настройки по умолчанию: комиссия 7 %, Pro 3 %, сроки, минимальный вывод. |
| `…0200_sauda_logic.sql` | Внутреннее: сессии, `sauda.money()` — единственное место, где меняется баланс, оформление заказа, завершение и возврат сделки, фоновые задачи. |
| `…0300_sauda_api.sql` | Функции для сайта `public.sauda_*`: вход, витрина, лоты, покупка, заказы, отзывы, чаты, кошелёк, подписки… |
| `…0400_sauda_admin.sql` | Вход в админку по коду (`sauda_admin_claim`; сам код создаётся в 0100) и первая версия функции админки — действующая версия в 0600. |
| `…0500_sauda_seed.sql` | 63 игры и сервиса с разделами, демо-продавцы и 56 демо-лотов, задача раз в минуту, права доступа. |
| `…0600_sauda_live.sql` | Настоящие деньги (пополнение по коду, запуск), отмена вывода и исправления; новые версии функций из 0200–0400. |
| `…0700_sauda_levels.sql` | Уровни Sauda: опыт за сделки, ниже комиссия продавцу, кешбэк покупателю (настройка `levels`). |
| `…0800_sauda_goods_login.sql` | Вещи с доставкой подтверждаются сами только через 14 дней; подбор пароля закрывает вход только подбирающему (по адресу). |
| `…0900_sauda_games_admin.sql` | Админка «Игры»: добавить игру, разделы, эмодзи, цвет, свой логотип (хранится в базе, `sauda.games.logo`). |

## Как выложить обновление

### Сайт — файлы из `market/`
Через GitHub в браузере, без программ:
1. Откройте https://github.com/vcrfftrk9w-afk/-/tree/main/market и нужную папку (`js`, `css`…).
2. Откройте файл → карандаш ✏️ «Edit» → выделите всё, вставьте новый текст от ИИ → «Commit changes».
   Несколько файлов сразу: «Add file» → «Upload files» → перетащите файлы с теми же именами → «Commit changes».
3. Через 1–2 минуты сайт обновится сам: https://vcrfftrk9w-afk.github.io/-/market/ (обновите страницу).
   Android-приложение и этот архив тоже пересоберутся сами (раздел Releases → `sauda-latest`).

Можно выложить папку `market/` на любой хостинг (Netlify, Vercel, Cloudflare Pages) — данные останутся те же,
потому что база одна (адрес в `js/config.js`).

### Сервер — SQL
1. ИИ должен прислать **новый файл**, например `supabase/migrations/20261101000100_sauda_delivery.sql`,
   с `create or replace function …` / `alter table … add column if not exists …`. Старые файлы 0100–0900 уже применены —
   заново их не запускайте и не переписывайте.
2. https://supabase.com/dashboard → проект `lgsharkholmydihgtvis` → **SQL Editor** → «New query» → вставьте весь файл → «Run».
3. Положите этот файл и в GitHub, в папку `supabase/migrations/` — чтобы история сервера была полной.

## Правила для ИИ — чтобы ничего не сломать

- Сайт без сборки: никаких npm-пакетов и фреймворков на странице. Новый файл скрипта — добавить `<script>` в `index.html`
  (перед `js/app.js`) и в список `ASSETS` в `sw.js`.
- Вёрстка только через `html`…`` из `core.js` — он экранирует всё подставленное. `raw()` — только для своего проверенного HTML.
  Никогда не вставлять текст от людей через `innerHTML` напрямую.
- Каждый видимый текст — по-русски через `t('…')`, и сразу перевод в `js/i18n-kz.js`. Проверка: `node tools/sauda-i18n.js` (должно быть «нет перевода: 0»).
- Суммы из полей ввода — только через `Fmt.amount()` («5 000», «5000,50» → 5000).
- Деньги считает только сервер. Баланс меняется только через `sauda.money()` — каждое движение пишется в журнал `sauda.tx`.
- Функции для сайта — `public.sauda_*`, `security definer`, `set search_path = ''`, имена таблиц со схемой (`sauda.lots`).
  Ошибка — `raise exception 'код'`, функция ловит её и отвечает `{ ok: false, error: 'код' }`; текст для человека — в `ERRORS` в `core.js`.
- Новая функция `public.sauda_*` должна быть доступна сайту: в конце файла миграции — блок «права» как в `…0700_sauda_levels.sql`.
- Тестовый режим: пока он включён, пополнение бесплатное. «Запуск с настоящими деньгами» обнуляет тестовые балансы и необратим.
- Меняешь SQL-функцию — бери её **последнюю** версию: одна функция может быть в нескольких файлах (например, `sauda_admin` — в 0400 и 0600, `sauda.complete` — в 0200 и 0700); действует та, что в файле с бо́льшим номером.
- `sauda.html` и архив собирает `tools/sauda-pack.js`: он встраивает только `css/sauda.css` и скрипты, подключённые ровно как `<script src="js/имя.js"></script>` (имя — строчные латинские буквы, цифры, дефис). Стили — только в `css/sauda.css`, картинки — в `img/` или `icons/`.
- Файл с изменениями присылать **целиком**, с путём.

## Проверки на своём компьютере (если ИИ умеет запускать команды)

Нужны Node.js 18+, PostgreSQL 16 и `npm i pg playwright` (для браузерных проверок — `npx playwright install chromium`).
Команды для Linux и macOS, **не от root**. Ubuntu: `export PATH=/usr/lib/postgresql/16/bin:$PATH`;
macOS: `brew install postgresql@16 && export PATH="$(brew --prefix postgresql@16)/bin:$PATH"`. На Windows — через WSL (Ubuntu).

```bash
# база для проверок (сокет /var/tmp/saudapg, порт 54329) — один раз:
mkdir -p /var/tmp/saudapg && initdb -D /var/tmp/saudapg/data -U postgres
pg_ctl -D /var/tmp/saudapg/data -o "-p 54329 -k /var/tmp/saudapg" -l /var/tmp/saudapg/log start
# перед КАЖДЫМ прогоном проверок (они переводят базу в боевой режим, а сервер запоминает список функций при старте):
npm run db                    # чистая база со всеми миграциями
npm run dev &                 # (пере)запустить: сайт и «Supabase» на http://localhost:8793/market/
npm run test:api              # 22 проверки сервера: сделки, деньги, права, уровни, вещи, вход, игры, запуск с настоящими деньгами
npm run test:ui               # 14 сценариев в браузере
npm run i18n                  # все ли тексты переведены
npm run pack                  # собрать заново этот архив и sauda.html (нужен git и zip)
```

## Что никогда не давать ИИ

Не вставляйте в чат с ИИ и не кладите в архив: **код администратора**, пароль базы данных, секретный ключ Supabase
(`sb_secret_…` или `service_role`), логины и пароли от GitHub, Supabase и Kaspi. Для работы ИИ всё это не нужно:
адрес базы и публичный ключ в `market/js/config.js` — не секрет (таблицы закрыты, доступны только функции `sauda_*`).
Ключ подписи Android-приложения (`android-sauda/app/sauda.keystore`) уже лежит в открытом репозитории — для Google Play
сделайте свой и храните его отдельно.

## Своя копия с нуля (если нужен свой сервер, а не этот)

1. Создайте проект на https://supabase.com (бесплатно). Database → Extensions → включите `pg_cron`
   (без него фоновые задачи идут попутно с запросами — тоже работает).
2. SQL Editor → по очереди выполните 9 файлов из `supabase/migrations/` (0100 → 0900), каждый целиком.
3. Project Settings → API: «Project URL» и publishable (anon) key → впишите в `market/js/config.js`
   (`api: 'https://<проект>.supabase.co/rest/v1/rpc/'`, `key: '…'`).
4. Код администратора: в SQL Editor `select v #>> '{}' from sauda.config where k = 'admin_code';`
   На сайте: «Профиль» → «Настройки» → «Для администратора» → введите код.
5. Выложите `market/` на хостинг (GitHub Pages, Netlify…).

## Что можно улучшить дальше

- Автоматический приём оплаты картой (Kaspi Pay / Freedom Pay / Halyk ePay) — нужен договор с платёжным сервисом и ИП/ТОО;
  Edge Function по уведомлению сервиса делает то же, что кнопка «Зачислить» в админке.
- Вещи с доставкой: отдельные поля «способ доставки» и «трек-номер» с отслеживанием (сейчас — текстом при выполнении).
- Push-уведомления на телефон, поиск с опечатками, верификация продавцов по документам.

Подробное описание возможностей — `market/README.md`.
